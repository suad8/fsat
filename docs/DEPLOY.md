# النشر على Railway

1. New Project ← Deploy from GitHub repo ← `suad8/fsat` (الفرع `claude/brave-ritchie-qxuly6` أو الفرع الرئيسي بعد الدمج).
2. أضف **Volume** للخدمة وركّبه على `/data` (يحفظ قاعدة SQLite والملفات المرفوعة).
3. المتغيّرات **المطلوبة** (التطبيق يرفض الإقلاع أو البذر إن كانت ضعيفة):
   - `AUTH_SECRET` — عشوائي قوي ≥ 32 حرفًا: `openssl rand -base64 48`
   - `ADMIN_EMAIL` — بريد حساب المالك (يُنشأ عند أول تشغيل فقط)
   - `ADMIN_PASSWORD` — كلمة مرور **قوية** (12+ حرفًا بتنوّع)؛ كلمات مثل `333` أو الافتراضية تُرفض في الإنتاج
   - `NEXT_PUBLIC_SITE_URL` — رابط الموقع الكامل `https://…` (يُقرأ وقت البناء؛ اضبطه قبل أول بناء)
   - `TRUSTED_PROXY_HOPS` — اتركه 1 على Railway (وكيل واحد أمام التطبيق)
4. البناء: `npm run build` (يُجهّز قاعدة مؤقتة نظيفة ثم يبني — لا يعتمد على `dev.db`).
   التشغيل: `bash scripts/railway-start.sh` (هجرات ← بذر أول مرة ← تشغيل). فحص الصحة: `/api/health`.
5. الصفحات تُجدَّد كل دقيقة، فما تعدّله الإدارة يظهر للعميل خلال دقيقة حتى بعد نشر جديد.

## بعد أول نشر
- ادخل `/admin` وغيّر بيانات التواصل والرقم الضريبي (المؤقتة تظهر تنبيهًا في اللوحة).
- راجع `docs/SECURITY.md` (قائمة التحقق قبل النشر) و`docs/QA.md`.
- نسخة واحدة فقط من الخدمة (SQLite). للتوسّع: PostgreSQL (انظر `docs/DATA.md`).
- بوابة الدفع: غير مربوطة بعد؛ الطبقة جاهزة في `src/lib/shop/payments.ts` (تحويل بنكي/دفع عند الاستلام فعّالان، والبطاقة «قريبًا»).
